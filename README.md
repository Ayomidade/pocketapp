## Setup and development

## Local setup

### 1. Install dependencies

Use Node.js 22 (the version used in CI), npm, and Docker Compose. You will also need an Android/iOS device or emulator to run the mobile app.

```bash
git clone https://github.com/Ayomidade/pocketapp.git
cd pocketapp
npm ci
```

### 2. Configure the backend and local services

Copy the shared environment template to the repository root:

```bash
cp .env.example .env
```

Edit `.env` and set the following values for the included Docker services:

```dotenv
POSTGRES_USER=pocketops
POSTGRES_PASSWORD=replace_with_a_local_password
POSTGRES_DB=pocketops_dev
DATABASE_URL=postgres://pocketops:replace_with_a_local_password@localhost:55433/pocketops_dev
REDIS_URL=redis://localhost:56380
```

Use the same database credentials in both places, and URL-encode special characters in the `DATABASE_URL` password. The Compose ports are **55433** for PostgreSQL and **56380** for Redis; the template’s default URLs use different ports.

Replace the JWT secret placeholders with independent random values, and set `CREDENTIALS_ENCRYPTION_KEY` to a base64-encoded 32-byte key. Generate each value separately:

```bash
# Run once for each JWT secret.
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"

# Run for CREDENTIALS_ENCRYPTION_KEY.
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

The backend loads `server/.env` first, then the root `.env` as fallback. Existing process environment variables take precedence.

### 3. Configure the mobile app

Create `mobile/.env` containing only the public client settings:

```dotenv
EXPO_PUBLIC_API_URL=http://localhost:4000/api/v1
EXPO_PUBLIC_APP_SCHEME=pocketops
```

For a physical device, replace `localhost` with your development machine’s LAN address. For the Android emulator, use `10.0.2.2`. The API must be reachable from the device.

Do **not** copy the full environment template into `mobile/`. GitHub private keys, OAuth secrets, encryption keys, and Render credentials belong on the server. Expo public variables are included in the client bundle.

### 4. Start the database and apply migrations

```bash
docker compose up -d
npm run migrate
```

Optionally load the demo seed data:

```bash
npm run seed
```

### 5. Run the app

Run each command in a separate terminal from the repository root:

```bash
npm run dev:server
```

```bash
npm run dev:worker
```

```bash
npm run dev:mobile
```

The API defaults to `http://localhost:4000`, with application routes under `/api/v1`. Check that it is responding with:

```bash
curl http://localhost:4000/health
```

The worker process handles queued health checks and push delivery. Follow the Expo terminal instructions to open the mobile app; native integrations and deep links may require a development build.

## Provider connections

To use live GitHub features, configure the `GITHUB_*` settings in the backend environment with your OAuth and GitHub App credentials. The default OAuth callback is `http://localhost:4000/api/v1/auth/github/callback`; use a reachable backend URL for device testing and external callbacks.

Render accounts connect through the app. The backend environment also defines the Render API base URL and webhook secret. Push delivery uses Expo notifications and the optional `EXPO_ACCESS_TOKEN`. See the [security architecture](docs/architecture/SECURITY.md), [notification architecture](docs/notifications/ARCHITECTURE.md), and [API specification](docs/api/openapi.yaml) for integration details.

## Development commands

Run these from the repository root:

| Command | Purpose |
| --- | --- |
| `npm run dev:server` | Start the API with Node watch mode |
| `npm run dev:worker` | Start BullMQ workers |
| `npm run dev:mobile` | Start the Expo development server |
| `npm run migrate` | Apply Sequelize migrations |
| `npm run seed` | Run database seeders |
| `npm run lint` | Lint server and mobile code |
| `npm run test:server` | Run the Vitest server suite |
| `npm run test:mobile -- --runInBand --watch=false` | Run the Jest mobile suite once |
| `npm --workspace=server run db:migrate:undo` | Roll back the latest migration |
| `npm --workspace=mobile run build:editor` | Rebuild the bundled CodeMirror editor |

## Stack and structure

| Location | Purpose |
| --- | --- |
| `mobile/` | JavaScript/JSX app using Expo SDK 52, React Native, Expo Router, React Query, and Zustand |
| `server/` | Node.js CommonJS/Express API, Sequelize migrations, and BullMQ workers |
| `docs/` | Product requirements, architecture, API specification, testing, and design references |
| `UI/` | Exported Signalframe screen references |
| `app/` | Separate native Android/Kotlin project |
| `docker-compose.yml` | Local PostgreSQL 16 and Redis 7 services |

The npm development commands below run the `mobile/` and `server/` workspaces.

## Engineering conventions

Read [AGENTS.md](AGENTS.md) before making changes.

- Keep `mobile/` in JavaScript/JSX and `server/` in CommonJS.
- Use [Signalframe tokens](mobile/src/theme/tokens.js) for operational screens; scope the Relay palette to brand surfaces.
- Verify the base file SHA before committing remote file edits.
- Require `Idempotency-Key` headers for commit, pull request, redeployment, and incident-resolution API requests.
- Never auto-resolve an incident from a single health check or a completed deployment.
- Add reversible Sequelize migrations in `server/migrations/` for database changes.
